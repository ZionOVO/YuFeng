# Coraza Windows `SecRxPreFilter On` 性能基准

本报告记录 `yufeng-edge` 当前配置在实验性 `SecRxPreFilter On` 下的独立检测等价与容量测量。它与 [`coraza-windows-performance.md`](coraza-windows-performance.md) 中的 `Off` 历史结果分开保存，不能把两份报告的数字混为同一条容量曲线。

本轮比较通过全部门禁：没有丢失或改写官方发现，没有新增良性命中；小请求与混合负载没有回退，64 KiB（二进制千字节）生产正文均有显著提升。这里的提升反映维护版发布、维护版引擎改动和预筛选开启的合并效果，不是预筛选开关的孤立因果实验。

## 2. 方法与数据完整性

从仓库根目录执行：

```powershell
.\scripts\coraza-benchmark.ps1
```

脚本固定每个子基准运行 3 秒、重复 5 轮，并分别使用 `GOMAXPROCS=1` 与 `GOMAXPROCS=32`。三个路径各覆盖 12 种请求形态；两份引擎各产生 360 条原始行，合计 720 条，得到 144 个引擎/路径/负载/处理器中位数组和 72 个官方对比组。每组都恰好有 5 轮，结果由脚本生成 `raw-results.csv`、`median-results.csv`、`comparison.csv`、`detection-checks.json` 与 `acceptance.json`。

检测检查命令为：

```text
go test ./lib/edgecore -run ^TestCorazaMaintainedEngine(PreservesOfficialDetectionGolden|SupportsOwnedLifecycle)$ -count=1 -v
```

官方黄金文件 [`coraza-v3.7.0-detection-golden.json`](../../../procedures/http-inspection-baseline/coraza-v3.7.0-detection-golden.json) 仍是 `Off` 对照元数据；维护版在 `On` 下通过同一检测等价比较。维护版新增的 4 个恶意样本发现来自已同步的规则修复，未新增良性命中。

## 5. 验收门禁

| 门禁 | 阈值 | 实测 | 结果 |
|---|---|---|---|
| 检测等价 | 无官方发现丢失或字段变化，无良性新增命中 | `detection_equivalent=true`；官方发现全部保留，维护版只在恶意样本增加 4 个已知规则发现 | 通过 |
| 小请求与混合负载 | 每秒请求数不得回退超过 10% | 72 组中最小变化为 `ReleaseProxy.ServeHTTP/read_no_body`、`GOMAXPROCS=32` 的 +12.94% | 通过 |
| 64 KiB 生产正文 | 至少一个形态提升不少于 20% | 最小提升为 `ReleaseProxy.ServeHTTP/natural_text_64_kib`、`GOMAXPROCS=1` 的 +2,849.34%；所有四种正文形态均超过门槛 | 通过 |
| 样本完整性 | 每组 5 轮 | 720 条原始样本、72 组对比均完整 | 通过 |

`acceptance.json` 的 `accepted` 为 `true`。这表示本轮维护版 `On` 配置满足当前 Coraza 替换门禁，不等于真实部署吞吐或第 99 百分位延迟承诺。

## 6. 使用边界

- 结果不包含真实套接字、传输层安全协议、内核网络栈、客户端慢读、上游网络抖动、模型侧、控制面或多进程调度。
- `ReleaseProxy.ServeHTTP` 使用内存响应写入器和内存上游传输，只代表规范化、同步检查、闸门与证据环的核心成本。
- 并行 `ns/op` 是聚合完成间隔，不能当作单请求平均延迟，更不能推出第 99 百分位延迟。
- 正文是固定合成形态；真实业务还需用脱敏回放补充方法、头、内容类型、压缩、解析错误和正文大小分布。
- 本轮在 Windows、`CGO_ENABLED=0` 下执行，未覆盖竞态检测、Linux、非一致内存访问架构或生产代理链。
- `SecRxPreFilter On` 仍是实验性配置。后续任何 Coraza、核心规则集或预筛选模式变化，都必须重新运行检测等价、安全测试和完整容量门禁，并生成独立结果目录。
