# Coraza Windows 检测等价与性能基准

本报告记录 `yufeng-edge` 从官方 Coraza v3.7.0 切换到自维护 Coraza 固定提交前的检测等价与容量门禁。2026-08-31 的正式结果满足替换条件：没有丢失或改写官方发现，没有新增良性命中，小请求与混合负载最差每秒请求数回退 6.54%，多个 64 KiB（二进制千字节）生产正文形态提升超过 20%。

这些数字是同机、无网络抖动的核心路径容量结果，不是企业部署容量证明。架构依赖策略见 [`architecture.md`](../../architecture.md) 的架构决策记录 041。

## 1. 检测等价结论

固定黄金文件 [`coraza-v3.7.0-detection-golden.json`](../../../procedures/http-inspection-baseline/coraza-v3.7.0-detection-golden.json) 由官方 Coraza v3.7.0 生成。比较键包含 Inspector、规则编号、攻击分类、分数、检查位置、选择器、阶段、核心规则集版本、规则清单摘要、检查档案摘要、四个检查面的覆盖度和最终拒绝状态。

| 项目 | 官方 v3.7.0 | 自维护 `151f051001b8` | 结论 |
|---|---:|---:|---|
| 固定案例 | 37 | 37 | 相同 |
| 官方发现 | 50 | 50 个全部保留 | 相同 |
| 恶意案例新增发现 | 0 | 4 | 只出现在恶意样本，不阻断 |
| 良性案例新增发现 | 0 | 0 | 相同 |
| 位置、选择器、阶段或覆盖度变化 | 0 | 0 | 相同 |
| 返回拒绝响应 | 0 | 0 | 保持仅检测模式，无策略不返回 403 |

新增的四个发现均为 `m-lfi-01` 至 `m-lfi-04` 上的规则 `932160`，攻击分类为命令注入，位置为查询参数。它们来自自维护仓已同步的上游 `fd673caa` 多重匹配修复；没有用自维护性能修改放宽检测。测试允许恶意样本增加发现，但任何官方发现缺失、字段变化、覆盖度变化或良性新增发现都会失败。

自维护版还通过网络应用防火墙实例重复关闭测试。官方 v3.7.0 没有实例关闭接口，官方临时副本只跳过该生命周期断言，不跳过检测黄金比较。

## 3. 命令与方法

从仓库根目录执行：

```powershell
.\scripts\coraza-benchmark.ps1
```

默认参数固定为每项测量 3 秒、重复五次，并分别设置 `GOMAXPROCS=1` 和 `GOMAXPROCS=32`。每项在计时前先运行一次所有请求形态，确认检查成功并完成预热。脚本对每个“引擎版本、基准、处理器数”要求恰好五个样本，取耗时、字节分配和分配次数的中位数，再由中位 `ns/op`（每操作纳秒数）换算每秒请求数。

若官方对照已经完整结束而后续运行中断，可复用同一正式目录：

```powershell
.\scripts\coraza-benchmark.ps1 -ResumeDirectory '.tmp/coraza-benchmark-20260831-125402'
```

续跑会核对御锋提交、测量时长、轮数与处理器列表，并验证复用结果每组恰有五轮。本次正式目录包含官方和自维护原始输出各 360 条、72 组五轮中位数；目录位于 `.tmp/`，不纳入版本控制。脚本会生成 `environment.json`、`raw-results.csv`、`median-results.csv`、`comparison.csv` 和 `acceptance.json`。

三个被测路径分别是：

- `BenchmarkCorazaDetectorSerial`：单工作协程调用 `CorazaDetector` 检查内核；
- `BenchmarkCorazaDetectorParallel`：多个工作协程共享一个调用方持有的 `CorazaDetector` 实例；
- `BenchmarkCorazaReleaseProxyCapacityParallel`：包含超文本传输协议（HTTP）请求规范化、Inspector 检查、Gate 裁决、证据环和无网络抖动的内存上游传输，不包含真实套接字。

并行基准的 `ns/op` 是所有工作协程的聚合完成间隔，不是单请求延迟。下表的每秒请求数等于 `1,000,000,000 / ns/op`。

## 8. 限制与使用边界

- 结果不包含真实套接字、传输层安全协议（TLS）、内核网络栈、客户端慢读、上游网络抖动、ModelSide、Brain 或多进程调度。
- `ReleaseProxy.ServeHTTP` 使用内存响应写入器和内存上游传输，只代表规范化、同步检查、闸门与证据环的核心成本。
- 并行 `ns/op` 是聚合完成间隔，不能当作单请求平均延迟，更不能推出第 99 百分位延迟。
- 每秒请求数是单个进程、一个共享 Coraza 实例在该工作站上的微基准容量；它不能直接外推到生产连接数、带宽或企业集群容量。
- 负载正文是固定合成形态。真实业务需用脱敏回放补充方法、路由、头、内容类型、压缩、解析错误和正文大小分布。
- 本轮在 Windows 且 `CGO_ENABLED=0` 下运行，不执行竞态检测；Linux、非一致内存访问架构、多网卡和生产代理链仍需另行测量。
- 所有正式成绩均保持 `SecRxPreFilter Off`。开启预筛选的平行仓实验不能与本表混用，也不能作为御锋生产成绩。
