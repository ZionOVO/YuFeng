# 数据面性能基线

## 1. `v0.1.0` 模型旁路预算

当前冻结目标来自 [`lib/kernel/limits.go`](../lib/kernel/limits.go)：每个 `yufeng-edge` 进程每秒 2000 个请求；启用异步模型旁路后，请求路径第 99 百分位延迟相对关闭旁路基线最多增加 1 毫秒。Edge 到 ModelSide 与 ModelSide 到 Brain 是两条独立有界队列；任何队列、模型、Brain 或磁盘状态都不得让请求处理协程等待。

发布容量门禁固定覆盖五个场景：

1. 旁路关闭；
2. ModelSide 空闲并持续取走输入；
3. ModelSide 满载，Edge 输入队列已满；
4. Brain 断连，ModelSide 继续推理且结果队列形成有界积压；
5. Brain 磁盘变慢，结果消费变慢但 Edge 输入仍独立推进。

`make performance-live` 以每秒 2100 个请求的供给速率给 2000 个请求/秒目标留出计时器抖动余量，并输出 `model-bypass-capacity/v1` JSON。普通 `go test` 只执行快速非阻塞不变量测试；五个一秒定速窗口仅在显式性能门禁中运行。

## 2. 2026-08-24 工作树预检

本次测量环境为 Darwin arm64、Go 1.27.0。它证明当前工作树的请求路径与两级有界队列满足预算，不等于软件已经发布；正式部署结论仍须把 `v0.1.0` 发布清单摘要绑定到目标环境的容量记录。

| 场景 | 实际吞吐（请求/秒） | 第 99 百分位 | 相对关闭旁路增量 | 队列行为 |
|---|---:|---:|---:|---|
| 旁路关闭 | 2100.89 | 186 微秒 | 0 | 无旁路队列 |
| ModelSide 空闲 | 2100.70 | 193 微秒 | 7 微秒 | 输入及时排空，无丢弃 |
| ModelSide 满载 | 2100.73 | 221 微秒 | 35 微秒 | 输入队列保持有界，2100 次旁路丢弃均立即返回 |
| Brain 断连 | 2100.63 | 291 微秒 | 105 微秒 | 结果队列深度 32，2068 次上报重试和高优先级丢弃不反压 Edge |
| Brain 磁盘变慢 | 2100.70 | 183 微秒 | 0 | 结果队列深度 32，2068 次重试与 2019 次普通结果丢弃不反压 Edge |

五个场景均高于每秒 2000 个请求，且最大第 99 百分位增量为 105 微秒，低于 1000 微秒预算。满载、断连与慢盘场景必须出现预期的有界丢弃或重试，否则门禁失败；因此“通过”不能由空场景冒充。

## 3. 历史反向代理基线

2026-08-21 的历史固定环境使用 Docker Desktop 27.5.1、aarch64、12 个逻辑处理器、8.217 GB 内存、Coraza 开放全球应用安全项目核心规则集 4.25.0 和偏执级别 1。它测得 20000 个良性请求以每秒 2000 个请求运行时，直连上游第 99 百分位为 1.097 毫秒，Edge 为 2.653 毫秒，额外 1.556 毫秒；目标负载 Edge 内存峰值 123102822 字节。

该历史测量还记录了 2048 个并发请求全部成功，以及 4224 个并发请求触发 4096 个请求硬边界和 128 个 HTTP 503；后者内存峰值 766194483 字节，超过 512 MiB 预算。它只用于保留旧反向代理与过载事实，不能替代 `v0.1.0` 五种模型旁路状态的目标环境复验。
